## Recommended fix bundle → v0.5.1

### Bundle A — Person-photo plumbing (N1, N2, N3, N4)

Single cohesive cluster; all touch the v15 person-photo/portrait feature. Each
fix is small (~5-20 lines) but N1 and N2 need matching regression tests
(`GalleryPhotosTest.kt` already covers the encounter path — extend to
portraits). Estimated: 1 focused session.

### Bundle B — Backup log hardening (N6)

Two-line proguard change OR a `BuildConfig.DEBUG` gate on the log call.
Trivial, ship with A.

### Bundle C — Backup atomicity (N5)

Larger change; needs a staging directory pattern for media entries so the
DB commit only happens after every blob is on disk. Testable via a
regression test that injects an `IOException` mid-ZIP-loop. Estimated:
1 focused session on its own. Fine to ship in v0.5.1 too or defer to v0.5.2.

### Defer

- Q1 (INSERT OR REPLACE cascade): behaviour change; write a DECISIONS entry
  first, decide "wipe first vs merge", then implement. Not urgent — restore-over-
  existing is a rare flow, and today's restore-from-scratch UX steers users
  toward "delete all data → import".
- Q2 + Q3 orphans: bundle with the 9 other pre-existing orphans Lens 7 spotted
  in a strings-hygiene pass.
- Lens 4 REFAC: pick up if a filter feature has to be added to both VMs
  (that's when the dup burns).
